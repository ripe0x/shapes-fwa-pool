INTERPRETATION AND LIMITS

Seven test functions passed across these two runs. The fuzz test ran 256 histories
of 160 steps, or 40,960 randomized model steps. Each scale case also compared the
reference after 64 randomized steps, alongside explicit measured transitions.

The scale fixture creates 11,301 bookkeeping positions through separate calls.
Its total setup and repeated reference scans require the explicit larger test
budget. An earlier attempt using the default test budget stopped before finishing
10,000 positions. Individual measured kernel calls remain bounded and separately
asserted below 16,777,216 gas. These whole-test gas totals are not transaction gas
estimates for a deployed vault.

Each gas measurement cools the target account and storage, then invokes a separate
meter contract so the reference model's growing memory does not alter the measured
call frame. The quoted NAV measurements cover the pure accounting kernel and its
external harness call. They exclude FWA reads, receipt and journal completeness
guards, share issuance, redemption processing, and other complete checkpoint work.

The independent reference stores one custody record per asset and fully scans the
array at each comparison. It derives tracked principal, idle inventory, active
backing, active count, fee debts, allocation exposure, the ceil-debt correction,
and pending fees without reading the kernel aggregates. Each quantity has its own
assertion before the final NAV comparison, so shared cash and fee-credit inputs
cannot mask an incorrect kernel principal or fee total.

Cash and fee credit are deliberately external inputs to the pure kernel. This
model tests their contribution to NAV and models cash changes independently, but
does not authenticate actual FWA payments or prove the external fee accumulator.
The separate deployed-contract fork tests establish that integration boundary.

These are 10,000 pure accounting positions, not 10,000 live FWA listings. No FWA
selection or VRF behavior is asserted by this file. The real-FWA adapter and the
full production share accounting retain their own integration and release gates.
