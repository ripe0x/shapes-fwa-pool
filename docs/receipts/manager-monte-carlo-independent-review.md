[Probability summaries](../../sim/manager_monte_carlo.py#L75) use per-window Wilson intervals and weighted Bonferroni-window bounds for the mixture. These and the normal mean intervals are approximate, not exact finite-sample coverage guarantees. The final report must state achieved uncertainty. There is no outcome-dependent stopping, seed selection or production hurdle.

[The request tape](../../sim/forward.py#L322) is created from the fixed external acquisition-event order before manager actions occur, includes refunds and repeated exit-tail events, and separates selection, response and keep domains. Conditional responses do not advance later request draws. [The financial execution path](../../sim/forward.py#L616) consumes one tape row per external completion. ## Independent final-output plausibility check

Before examining final returns, the reviewer independently derived an additional diagnostic from selection probabilities. Immediately before each successful external request, let n be the manager's active listing count and W the total inverse-backing weight. The engine gives each own listing approximately k/W ETH in fees and selects listing i with probability (1/B_i)/W. Therefore expected selected backing is n/W ETH, and the conditional expectation of `accrued fees - k × selected backing` is approximately zero. Adaptive position counts, cash/budget constraints and a bounded exit stopping time preserve this relationship because the active book is determined before the independent current selection draw. Fee floors introduce only a small downward rounding drift. This tests stochastic fee/selection consistency; it does not validate real-world demand or purchaser assumptions.

Every path, including zero-selection paths, must enter that residual's fixed-window stratified mean and uncertainty. Never condition on profitable paths or completed exits unless all planned exits complete. Manager rows do not save the local `selected_backing` counter. For completed .03-backing paths in this forced-bid model, it is exactly `backing_lost_wei`: responsive purchasers bid, silence chooses NFT reclamation and all accrued fees have been collected. At .15/.21 backing, that field also contains the principal of kept packs, so it cannot replace selected backing. Using selection count times nominal backing there would be an explicitly approximate check because proposals have small quantized offsets. Incomplete paths can reconstruct accrued fees from cash fees, external credit and unharvested listing fees, but cannot reconstruct exact selected backing from the saved fields; they must not be dropped to manufacture a zero-residual population claim.

For the .03 all-bid Fresh case, write X for selected backing, C for created packs, m=.0015 ETH for the three paid mint fees per pack, and F for fees. Completed owner net is `(F-kX)+(k-1)X-mC-keeper payments-owner wallet gas`. Each fresh pack can be selected at most once, so selections S satisfy S≤C and X is approximately .03S, with only the very small proposal offsets. Since `(k-1)×.03≈.001153815<m`, expected owner-only net is negative under these assumptions even before gas, if the fee/selection residual has mean zero. This is an expectation argument, not an assertion that every path or every finite-sample mean must be negative. Adding creator accrual for a verified common economic owner would answer a different question.

Any residual confidence interval is a diagnostic, not a pass condition. One nominal95% interval can miss zero in a correct engine; multiple cells increase false flags. The two .03 residual comparisons can use individual97.5% intervals for a separate nominal95% family, or be explicitly unadjusted diagnostics. No seeds should be rerun to make zero fall inside an interval. Final residual values remain pending; no additional simulation was run to derive this check.
