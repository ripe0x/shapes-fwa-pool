# Individual manager: expanded reuse-only assessment

**Decision.** The 0.03 ETH, three-paid-Shape manager at provisional 0.21 ETH backing has a **positive conditional mean** in the archived-month replay, but meaningful losing paths and an unresolved keeper bootstrap problem. This does **not** establish a viable unattended production default or an APR. Keep the manager-only package unsigned and both PRs draft. The shared vault remains closed.

## What was run

The [frozen result](../../sim/out/manager-measured-a10-release/summary.json) contains **320 settings rows from 40 distinct scenario paths**. The recorded-month comparison has **16 request-keyed paths**: eight seeds in each of two archived 30-day request windows, under each of two buyer-response regimes. These still share only **two archived demand tapes**; changing the selection seed does not create a new market month. Quiet and early-burst-then-zero stress each add two paths per buyer regime. Every path uses the same eight executable settings cells: 0.005/0.006 ETH reserve, observed 0.0005/historical accepted 0.001 ETH mint fee, and 0.2/0.5 gwei, with 0.21 ETH backing fixed. All 320 owner-paid exits completed within the stated 0.01 ETH wallet limit; the largest ledger gap was **0 wei**. The [new real-counterparty packet](manager-measured-sync-multi-later-first.json) closed the additional two-position `960000:1:2` gas shape. This run is a conditional replay of archived demand and synthetic buyer responses; it is **not a month of transactions by a deployed manager**.

At the observed mint fee and 0.2 gwei, every path starts with 0.5 ETH, two 0.03 ETH packs and **six directly paid primary Shape mints**. FWA cash collected is kept separate from assets consumed: a bid return consumes the posted backing and returns the pack; a keep returns backing less settlement fee and consumes the pack's 0.03 ETH principal. The owner pays wallet gas for exit. Values below are means within the stated path count.

The 0.5 ETH starting balance is an assumed evaluation input. The [public wallet readback](manager-a10-public-readback.json) found only **0.177336592479995704 ETH** at block 26,494,800, so the unsigned 0.5 ETH creation template lacks **0.322663407520004296 ETH plus wallet gas** at that snapshot.

## Reserve and operating conclusion

The conservative **one maximum-work listing batch plus journal/prune** keeper cash envelope at 0.5 gwei is **0.0055305 ETH**. The current unsigned **0.005 ETH reserve** is short **0.0005305 ETH**. An evaluated **0.006 ETH reserve** leaves **0.0004695 ETH** headroom if the owner supplies the extra **0.001 ETH**. It raises the one-position funding envelope by that amount and withholds it from new exposure; unused cash returns on exit. Across **160 matched path pairs** spanning all settings and stress regimes, the reserve increase changed owner net by **zero** at the 0.5 ETH opening used here. It is a liquidity correction, not a return improvement.

The keeper's starting sync acceptance uses 93% of its RPC gas estimate. For one actual paired fork work shape it predicts **0.0002192938 ETH** cost against **0.0001520186 ETH** offered at 0.2 gwei, so it declines. That receipt actually billed **0.0001002192 ETH** gas and would have had positive margin. The ratio needs three successful sync receipts to recalibrate; other contexts bill up to 91% of estimates, so a single lower global ratio could make them lose money. This is an **unattended-service blocker** even though owner-paid recovery can complete exit. The 320-row positive conditional mean reflects archived fees on initial exposure while ordinary sync stalls; it is not evidence that the full maintenance/relist cycle works without owner intervention.

The smallest operational workaround is for the owner to use the existing bounded, wallet-funded recovery path when a sync is needed. A keeper-only product needs a separately validated context-aware acceptance/payment change. Lowering the account-owned backing target could reduce bid-return losses without changing the 0.03 ETH recipe, but the one-to-one 0.03 ETH backing case is currently inadmissible, and buyer choices and fee earning would change. No lower backing value is recommended from this fixed-backing replay. The 0.006 ETH reserve is preferable **only if** the owner elects to fund this speculative manager; it is not an approved production default.

The [receipt verification](manager-measured-verification.md) and [independent A10 review](manager-a10-independent-review.md) define the evidence boundary. Four earlier packet writer revisions were not preserved; their billed receipts, work events and paired prestates are checked, while RPC estimates are writer-recorded. The new `960000:1:2` packet's writer is source matched. The verifier now binds every transaction to both its packet and hash because isolated forks can repeat a hash in different states.

**Things that don't make sense.** Two draws gave a negative mean while 16 recorded paths gave a positive one; neither can predict future activity. The keeper leaves profitable measured sync work undone under its starting estimate rule, so passive fee accrual and a funded exit are not a proven unattended operating strategy. More reserve cash does not offset a 0.21 ETH bid-return backing loss.
